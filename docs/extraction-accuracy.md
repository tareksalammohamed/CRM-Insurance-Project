# Extraction and import accuracy

Document extraction proposes values; it does not save records. Customer and policy extraction share the same editable-control discovery, typed validators and review UI. Each control uses its own associated label. Hidden/read-only/disabled controls and internal account/customer/owner IDs are excluded; national_id remains an extractable customer field.

The prompt defines insurance field meanings and person roles explicitly. Local checks reject malformed numbers/dates, enforce exact select options, flag source-label conflicts and inconsistent national ID/birth dates, and compare the policy document subject with the selected customer's name. Missing evidence, uncertain identity or conflicting meanings are not preselected. The review shows original entered values, proposals and source evidence. Applying rechecks current values, locks and hidden form context before setting any field.

Spreadsheet import exposes a one-to-one source-column review with examples. An AI proposal, duplicate/ambiguous headers or a non-explicit net-premium source require confirmation. Confirming rereads the original file without an additional model request. The standard template follows its existing direct route. Net premium is never selected by taking the smallest number. Import-only premium truncation is retained. Native numeric/date cells are authoritative; unsafe numeric identifiers and percentage-formatted amount cells require correction. Similar agent names are suggestions only; duplicate exact names require an explicit in-scope account selection.

Document imports preserve page/field provenance and require each proposed record to be reviewed. Identical repeats are deduplicated; conflicting policy records remain visible and blocked. Review flags survive checkpoints and are enforced again at the send boundary. Excluded/corrected rows are revalidated before sending. Partial extraction preserves completed pages and resumes from the next incomplete page. An explicitly incomplete or malformed model page is not advanced.

PDFs render up to a 2000-pixel long edge instead of being capped at the original small page viewport. PDF resources are released after rendering; the four-page form limit is disclosed rather than silently hiding the remainder. Existing gateway/provider settings, database RPCs, business formulas, printing and records are unchanged.

Verification: semantic/schema/parser/review/import-flow regression tests, synthetic PDF browser checks at mobile and desktop sizes in light/dark themes, the complete test suite, typecheck, lint, help coverage, closing SQL and eight populated PDF print scenarios. Browser/model fixtures verify routing and validation; they do not establish OCR accuracy for every possible real document. Unclear handwriting or missing source evidence still needs a person's verification against the original document.
